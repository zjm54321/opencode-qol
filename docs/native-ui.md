# Native UI and its bundled skill

`kernel/plugins/native-ui` registers `native_ui({source, title?})` as a native built-in tool. Its short description directs the model to load the **native-ui** skill before the first call. Non-primary agents receive deny rules for the tool and skill. It does not replace desktop-bridge's RPC interface.

The source language is OpenUI Lang. Official MIT `@openuidev/lang-core` **1.1.0** parses and validates against the Zod library. Final incomplete input, unresolved references, unknown components/actions, non-http(s) URL data and safety limits fail the actual tool call with line/column diagnostics. Successful output is a short acknowledgement; history retains the program in `state.input`, not in model-facing output.

`bun kernel/plugins/native-ui/scripts/generate-catalog.ts` generates `kernel/plugins/native-ui/catalog.json`. The JSON preserves OpenIntelligentUI's component names and positional prop order, includes JSON Schema types, reactive flags, parser version and limits. FluentCode embeds an identical copy; its focused conformance runner checks byte equality. Use `--check` to detect a stale generated catalog.

`kernel/defaults/skills/native-ui/SKILL.md` links the language, behavior/safety/design, worked examples, error recovery and full component catalog. Generate `references/components.md` with `bun kernel/plugins/native-ui/scripts/generate-skill-reference.ts` (or check it with `--check`). This script uses the same library/schema and examples as the validator; tests compare the generated Markdown byte-for-byte and validate all 68 fenced programs across the skill.

Source preparation copies the skill with all other `defaults/skills` into packaged assets, registers that directory in the lowest-priority global `skills` config, and mirrors it beside start-work/image-generation in OMO's bundled skills. The OMO custom registry includes native-ui for the orchestrator, so installer synchronization uses the normal skill path. Host discovery reads SKILL.md frontmatter and filters availability by skill permissions; loading the skill includes its base directory and resource paths. No separate reference tool is registered.

The current plugin registers native_ui for all clients, and OpenCode 2.2.5's plugin/skill API exposes no client capability for FluentCode-only discovery. The skill declares that it requires FluentCode and native_ui rather than guessing a client from platform or environment. Only FluentCode renders the native transcript card; no client-detection mechanism is added here.

The catalog has **57 components**: the upstream names except HtmlView, plus native Video, Audio and ImageGallery. Image/map/media resources load only after the user's click over HTTPS. @OpenUrl/Link require confirmation. @ToAssistant uses the guarded normal composer and queues while busy. Maps take WGS-84 coordinates and convert for the selected provider; YouTube opens in the in-app browser. Cards cannot run commands or edit files. Query/Mutation/@Run are parseable but show **未支持** and do not execute.

Measured with **o200k_base**, the native_ui description falls from **1,061 tokens / 4,410 characters** to **258 tokens / 1,240 characters**. Removing the old 45-token reference description reduces combined always-on tool text from **1,106 to 258 tokens**. Token counting tooling is not a production dependency.

Run focused server checks with `bun test kernel/tests/qol-native-ui.test.ts kernel/tests/qol-tui-defaults.test.ts`, or all QoL checks with `bun test kernel/tests/qol-*.test.ts`. The existing cross-client catalog/fixture check defaults to `/mnt/c/src/fluentcode-lanes/native-ui-v1`; set `NUI_FLUENTCODE_ROOT` to check another checkout. Its byte-equality assertion requires the same line endings. No server build, deployment or running-opencode replacement is needed.
